# 共用宽带迁线后的来源覆盖补领的演练来源

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。

## 本地运行

使用 Node.js 22.23.4。只使用 Node.js 自带的运行库。

执行 `npm test` 检查合成来源的接口。执行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

## 接口资料

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/station` | edge 表示观测端口，domain 表示设备号作用域。trace 可用来关联单一会话，seq 只在端点内连续。 |
| `/source/work` | mapping 有生效区间及线路范围，同域设备同时为不同业务保留在不同端。各区间左闭右开。 |
| `/source/care` | 客服结案按工单和明确业务线回访，关单记录保存采用的时间与覆盖依据。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。来源记录键与业务身份分别定义。`next` 为下一页偏移，末页为 `null`。回放阶段中的记录按到达顺序可查。

控制员通过 `POST /control?stage=2` 切换到第 2 阶段，服务会保留更早已可查的记录。每次换阶段后按根路径返回的 `stage` 确认切换成功。

会话来源用 `GET /session-window` 补领指定区间。参数为 `edge`、`gateway`、`line`、`from`、`until`。端点为 E-原 或 E-备，业务为村网或办公，时间为半开区间的 HH:mm。回包携带端点声明的保留边界 `floor`、常规留存长度 `retainMinutes`、独立覆盖声明 `covered` 和仍可取到的 `records`。普通来源接口保留的是到达记录回放；`/session-window` 反映该阶段站点还实际可补的数据。主动查询返回的数据以当前 floor 为准。
